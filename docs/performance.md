# 实测性能

原始数据：`backend-performance.json`、`web-performance.json`；测量脚本分别为 `services/model-api/scripts/benchmark.py` 和 `scripts/measure-web.mjs`。结果来自共享 Linux 云环境，不是隔离硬件的保证值，没有 FPS 或 Lighthouse 分数。

## 前端

Chromium 155.0.8059.79 headless，1440×1000 桌面与 390×844 触控视口。手机是同一主机上的模拟，不等价于真实手机。静态构建通过普通本地 HTTP 服务器从 `/origin-ai-lab/` 子路径提供，没有网络 / CPU 限速。

| 记录 | 桌面 | 手机视口 |
| --- | --- | --- |
| 首次内容绘制 | 392 ms | 392 ms |
| 首页入口可交互（含浏览器自动化等待） | 604 ms | 511 ms |
| Layer + Head 切换中位数（5 组，含自动化往返） | 78.8 ms | 20.4 ms |
| 是否请求三维代码块 | 是 | 否 |
| 稳定后 2 秒内 rAF 回调 | 0 | 0 |
| 稳定后 2 秒内 WebGL draw calls | 0 | 0 |

桌面在五轮 Home → Architecture → Explore 循环、等待释放并手动 GC 后，JS heap 从 9.30 MB 到 11.37 MB，增量 2.07 MB。它是短时回归观察，可能包含渲染器 / 库缓存，不是长期无泄漏证明。未观察到持续帧渲染；卸载时清理事件、计时器、tween 和 R3F 资源。

生产主 JS 约 433 KB（gzip 133 KB）；独立三维块约 975 KB（gzip 272 KB）；CSS 约 40 KB（gzip 8.8 KB）。实际构建保留三维块超过 500 KB 的提示。三维是按需加载，小屏与降低动态效果模式不会请求它，没有通过提高警告阈值掩盖体积。

静态实验约 57–69 KB 原始 JSON，按实验请求；矩阵超过 16 Token 后使用 Canvas，避免 4096 个单元的全量 DOM。64 Token 实时实验已经在桌面 / 手机 E2E 中验证。

## 后端

Python 3.12.14、PyTorch 2.10.0+cpu、3 个可见逻辑 CPU，模型设为 CPU / 2 线程 / float32。每种长度使用三个不同、未命中缓存的输入，HTTP 客户端连到同一个复用模型进程。

| 实际 Token | 前向中位数 | 完整 HTTP 中位数 | 典型 JSON | gzip 大小（离线测算） |
| --- | --- | --- | --- | --- |
| 5 | 261 ms | 293 ms | 68 KB | 18 KB |
| 16 | 485 ms | 514 ms | 342 KB | 101 KB |
| 64 | 425 ms | 702 ms | 4.45 MB | 1.15 MB |

非单调耗时来自共享 CPU 负载及短样本，不应解读为长度增加让模型更快。最初技术验证含网络获取的模型加载约 33.98 秒；HTTP 测量进程从本地权重缓存加载约 1.05 秒。正式三组短英文 fixture 的单次前向另测约 87–103 ms。两组数字均为实测，负载条件不同。

记录中的序列化时间包括摘要、Pydantic / 数值校验和一次真实 JSON 序列化：5 Token 约 13–22 ms；64 Token 约 183–234 ms。API 响应和传输还有额外成本。记录 RSS 从约 1.03 GB 到 1.16 GB，包含模型、库、缓存和临时张量，并非纯权重大小。

64 Token 缓存命中的 HTTP 实测约 780 ms，当前深拷贝和 JSON 序列化成本显著，所以本轮缓存没有表现出端到端提速。它确认没有再次执行模型前向，但不能宣传为更快响应。可在后续版本对不可变结果和编码后的响应做精确缓存优化；V1 优先保持记录一致性。

静态托管通常提供 HTTP 压缩。API 当前不自动压缩；表中 gzip 是对响应体的离线计算，不是假称测到了传输压缩。公开部署可在反向代理启用 gzip / Brotli。

没有在真实中端手机上验证 30 FPS，也没有测量 Safari、Firefox、GPU 或生产网络性能。
